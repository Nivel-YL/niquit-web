## Оптимизация стоимости редактора (дедуп сделан 24 авг, замер 31 авг)

**Что сделано (commit `290c631`):** две правки промптов в `scripts/blog_editor.py`, цель -
снизить стоимость прогона редактора с ~$4-7 до ~€0.50-1, без потери качества фактчекинга.
Корневая причина дороговизны выяснена по логам: главный расход - это web_search, а число
поисков масштабируется от числа флагов источников. Каждый выдуманный/неверно
атрибутированный источник, который ловит аудит, запускает до 2 поисковых фиксов (у G-02
17 авг было ~50 флагов = до ~300 поисков на одну тему). Правки:
1. `write_article`: жёсткое правило атрибуции - цитировать только источники, которые есть
   дословно в research-фактах, ничего не выдумывать, лучше опустить факт, чем придумать
   источник. Меньше флагов => меньше поисковых фиксов И меньше поиска в аудите.
2. `research_shared`: локальный (постранновой) research запрашивать только когда у темы
   есть реальное страновое измерение (цены, распространённость, законы), а не для
   универсальной физиологии/психологии.
**Осознанно НЕ трогал** потолки web_search (`audit max_uses=6`, `fix max_uses=3`) - они
срабатывают только на грязных статьях, то есть ровно когда поиск нужен; резать их = менять
качество на копейки. Сам фактчекинг не тронут.

**Замер 24 авг (прогон с одними промпт-правками 290c631, БЕЗ дедупа):** прогон прошёл
штатно (G-03/H-01/H-02, commit 6a42ec4), token-стоимость $4.01 (Haiku $3.19 + Sonnet $0.83),

на канонический URL без двойного слэша. Вероятно, остаточный эффект уже
исправленного (сессия 2026-07-25/26) бага двойного слэша в hreflang через
`localePath()` — Google мог проиндексировать эти URL ещё тогда, и с тех пор ничего
не просило его их забыть (нет ни 404, ни редиректа, только необязательная
canonical-подсказка). Вероятный частичный вклад в категорию «canonical differs»
(21 страница). Низкий приоритет — контент и canonical на этих URL корректны — но
если хочется закрыть, нужно либо правило схлопывания повторных слэшей на уровне
Cloudflare, либо редирект в самом Astro/middleware.

**Отдельное наблюдение, не факт проблема:** брендовый запрос `niquit` — 255 показов,
0 кликов, средняя позиция 20.26. Для запроса ровно по имени сайта позиция 20 —
низковато (обычно бренд-запросы у своего же сайта в топ-1-3), но у нас нет
исторических данных именно по этому запросу за прошлые периоды, чтобы сказать,
ухудшилось это или так было всегда с молодого домена. Не проверялось глубже.

## Что подтверждено закрытым (не баг, зафиксировать чтобы не переоткрывать)

- На зоне `niquit.app` в Cloudflare нет обычных Redirect/Page/Bulk/Transform Rules
  про trailing slash помимо описанных выше — пользователь проверил лично в
  дашборде 2026-07-26.
- `niquit.netlify.app` — не просто "не редиректит", а полностью удалён из GSC и не
  несёт вообще никакой функции; решение осознанное, не откатывать.
- `niquit-web.pages.dev` — оставлен специально (пользовательское решение), просто
  редиректится на apex.

## Известные ограничения (осознанные, не баги)

- Возвращающиеся браузеры с закэшированным старым редиректом `/method` могут по
  инерции зациклить у конкретного пользователя, пока не почистит кэш. Cloudflare не
  ставит `Cache-Control` на эти редиректы (проверено `curl -I`), так что не должно
  агрессивно кэшироваться, но не гарантия на 100%.
- `public/_headers` сознательно не используется для схлопывания слэшей — синтаксис
  допускает wildcard только как суффикс, нельзя описать "любой путь с слэшом на
  конце" без учёта растущего вручную списка слагов статей.
